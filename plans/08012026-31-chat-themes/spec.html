Why

SocMed's messenger works — send, react, unsend, live delivery — but every conversation looks identical. Messenger-style chat themes let friends personalize a thread's background, bubble colors, and composer accents, plus playful word-triggered animations. That makes 1:1 chat feel expressive without touching the feed or global app theme.

What

A shared per-conversation theme system: either participant can pick a look; both see the same design. Three customization layers ship together:

  • Chat Themes — bundled graphic presets (holiday, romance, music, movies, etc.) with background art + coordinated bubble/accent colors
  • Colors & Gradients — solid background colors or two-stop gradient mixes with derived bubble/button colors
  • Word Effects — curated word→animation catalog; when a message contains a trigger word, both participants see a one-shot effect in the bubble

Deliverables:

  • Schema — nullable theme JSONB (+ audit columns) on conversations
  • API — GET/PUT /api/messages/conversations/:id/theme; participant-only; validated preset/custom payload
  • Realtime — conversation:theme socket event so the peer's open thread updates without reload
  • Assets — bundled preset manifest + static backgrounds under frontend/public/chat-themes/
  • SPA — palette icon in thread header → theme picker sheet; CSS custom properties drive background, bubbles, composer accents; word-effect renderer in message bubbles

Done when:

  • Either participant can apply a graphic preset, solid color, or gradient; peer sees the same theme (socket or refresh)
  • Reset restores platform default B&W styling
  • Sending a message with a catalog trigger word plays the mapped animation for both sides
  • Non-participants cannot read/write theme; invalid colors/presets rejected
  • Bubble text remains readable (contrast guard) in light and dark app theme
  • Typecheck/build green; acceptance checklist passes or waived in writing

Context

Existing messenger — conversations, messages, message_reactions; REST under /api/messages; Socket.IO events message:new, conversation:updated, etc. Thread UI in MessagesPage.tsx → ThreadView; bubbles in MessageBubbleRow.tsx with hardcoded Tailwind color classes.

Closest analogs — reactionOptions.ts fixed allow-list; profile cover image pattern for background layers; ThemeContext for CSS-variable-driven styling (apply same technique scoped to thread root, not documentElement).

Layering — routes → controller → ChatThemeService → model; Zod validation in service; frontend via api/messages helpers only. Word-effect catalog is frontend-only constants + pure render helper — no DB.

API Surface

MethodPathBehavior
GET /api/messages/conversations/:id/theme Returns { theme, updatedAt, updatedBy } or null theme. Participant-only. Include in thread GET response optionally (avoid extra round-trip).
PUT /api/messages/conversations/:id/theme Body: theme payload or { reset: true }. Validates, persists, emits conversation:theme. Participant-only.

Thread GET enhancement: extend existing GET /api/messages/conversations/:id response with theme field so thread load is one request.

Socket: conversation:theme → { conversationId, theme, updatedAt, updatedBy } to both participants' user rooms.

UI / UX

  • Entry — Lucide Palette (or Sparkles) icon button in ThreadView header, right side. aria-label="Customize chat theme".
  • Picker — Sheet or dialog with tabs: Themes (graphic presets grid), Colors (swatches + custom hex picker if feasible without new deps), Gradients (preset gradient tiles). Live preview on selection; Apply commits via PUT.
  • Thread shell — Wrapper data-chat-theme sets CSS vars: --chat-bg, --chat-bubble-mine, --chat-bubble-theirs, --chat-accent, --chat-bubble-mine-fg, --chat-bubble-theirs-fg (foreground computed for contrast).
  • Bubbles — MessageBubbleRow uses vars instead of bg-foreground / bg-secondary when theme active.
  • Composer — Send button and icon buttons pick up --chat-accent.
  • Inbox — unchanged (no per-row theme preview in v1).
  • Accessibility — contrast helper ensures bubble text ≥ 4.5:1 against bubble bg; if fail, auto-adjust foreground to black/white.

Constraints

Must

  • Shared theme visible to both participants
  • Participant-only theme read/write
  • Preset allow-list validated server-side
  • Hex colors only for custom mode; no stored CSS strings
  • Socket push on theme change for open threads
  • Word effects client-rendered; message API body stays plain text
  • Readable bubbles in light + dark app theme
  • Constitution layering; theme logic not in React event handlers beyond apply-vars

Must Not

  • No custom user-uploaded chat backgrounds
  • No per-user local-only theme override layer
  • No rich-text / markdown message format change
  • No word effects stored or editable by users
  • No group chat theming (1:1 only)
  • No new npm deps without Revision Log justification

Out Of Scope

  • Theme preview in inbox list rows
  • Account Settings global chat defaults
  • Animated theme backgrounds (video/GIF)
  • Sound effects on word triggers
  • Theme history / undo
  • Nicknames, bubbles shapes, custom fonts

Risk

Level 3 — Structural Risk. Touches messenger core UI, adds persisted JSON with validation surface, ships static assets, and introduces animation rendering in the hot path (every message bubble). Blast radius: all messenger thread users, MessageService authz path, Socket.IO event surface, MessageBubbleRow render tree.

HazardBlast radiusMitigation
Illegible bubble text on custom colors UX / a11y Contrast utility picks foreground; block apply in picker if still failing
CSS injection via theme JSON Security Strict Zod schema; hex-only colors; preset IDs from allow-list only
Word-effect performance jank Thread scroll CSS-only animations; cap concurrent effects; disable on reduced-motion
Theme desync between peers Confusion conversation:theme event + include theme in thread GET
Asset bundle bloat Load time Optimize webp; lazy-load preset thumbnails; keep v1 ≤ 12 presets
Scope creep into rich text Architecture Word effects wrap plain text spans only — no markdown pipeline
Required pushback: This plan bundles theming + word effects + asset pipeline in one landing. If execution stalls, split word effects to a follow-up plan rather than shipping broken animations or skipping contrast guards. Do not add custom background uploads mid-flight.

Conversation message search

Status: In Progress

Execution branch: kylie/chat-search → dev

Why

People need to locate prior conversation messages without loading an entire history. The search feature adds an authenticated, scoped message-search route and a focused conversation UI.

What / Done

  • Search only messages in a conversation the caller participates in.
  • Use the partial trigram index migration owned by this PR.
  • Render matches safely and focus the selected message.
  • Keep migration ownership isolated from theme logging and message editing work.
  • Reconcile search with dev's theme-log timeline without dropping either behavior.
  • Run recorded acceptance before finalization.

Context and constraints

Relevant files: src/routes/messages.ts, src/controllers/messages/MessagesController.ts, src/services/MessageService.ts, src/models/MessageModel.ts, frontend/src/components/messages/ThreadView.tsx, and database/migrations/20260804120000_message_search_index.ts. Follow Routes → Controllers → Services → Models (§7.1); all data access remains in models (§7.4). No unrelated migrations or new dependencies.

Risk

Level 2 — Concern. Search migration requires pg_trgm, which staging/production must permit. The selected-message flow must not create an incoherent timeline. Mitigation: deploy preflight and explicit acceptance before merge.

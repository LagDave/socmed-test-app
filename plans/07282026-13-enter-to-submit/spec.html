Why

Comment and reply composers require tapping the Comment / Reply button. Users expect Return/Enter to send, especially on a keyboard. Today Enter only inserts a newline inside the textarea.

What

  • On the post-detail comment and reply textareas: Enter submits the form; Shift+Enter inserts a newline.
  • Keep the existing Comment / Reply buttons — Enter is an additional path, not a replacement.
  • If the body is blank or whitespace-only, Enter must not submit (no empty API call).
  • Feed post composer and other textareas are out of scope.

Done when: Enter sends a non-empty comment/reply; Shift+Enter still multiline; buttons still work; empty Enter is a no-op; frontend typecheck/build green.

Context

UI today: frontend/src/pages/PostDetailPage.tsx — bottom form onSubmit={onComment} + reply form onSubmit={onReply}, each with a Textarea and Button type="submit". No onKeyDown.

Textarea primitive: frontend/src/components/ui/textarea.tsx — thin styled forwardRef; do not bake submit semantics into the shared primitive (only comment/reply need this).

Closest pattern: page-local onKeyDown that calls preventDefault on Enter (without Shift) and triggers submit via form.requestSubmit() or the existing submit handlers — prefer requestSubmit() so HTML required / form wiring stay consistent.

Whitespace: trim check before submit (or in onComment/onReply / shared submitComment) so both button and Enter share one guard.

Constraints

Must

  • Enter (no Shift) → submit comment form / reply form when focused in that textarea
  • Shift+Enter → newline (default textarea behavior)
  • Blank / whitespace-only body → do not submit (button or Enter)
  • Keep Comment and Reply submit buttons visible and working
  • IME-safe: ignore keydown when event.isComposing / keyCode 229 so CJK input does not false-submit

Must Not

  • No change to Feed compose, Profile bio, or shared Textarea defaults for all pages
  • No new npm dependencies
  • No backend / API changes
  • Do not remove the buttons

Out Of Scope

  • Feed “What’s happening?” Enter-to-post
  • Mobile soft-keyboard “Send” accessory customization beyond normal Enter behavior
  • Visible hint text (“Press Enter to send”) unless needed for clarity — optional, not required
Decisions locked: Enter submits · Shift+Enter newline · keep buttons · comment+reply only · ignore blank/whitespace · IME-safe.

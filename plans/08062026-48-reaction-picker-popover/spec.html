Why

The prior reaction list was an anchor-bound popover. It could be constrained or poorly placed near viewport edges and was not a reliable small-screen experience. The reaction picker should continue to update the existing reaction summary while the people list opens in a stable, dismissible dialog.

What

Replace ReactionsListPopover with a portal-based, responsive ReactionsListDialog. The dialog opens from the existing reaction summary, supports all/current-emoji filtering, handles loading, empty, error, and truncation states, and uses a scrollable list. It appears as a bottom sheet on small screens and a centered dialog on larger screens.

Done when: selecting a reaction still updates its summary; opening the summary shows the correct people and counts; filter chips update the result set; backdrop, close control, Escape, and profile navigation close the dialog; and page scrolling is restored after dismissal.

Context

  • frontend/src/components/ReactionBar.tsx owns picker timing, reaction mutation, summary display, and the dialog open state.
  • frontend/src/components/ReactionsListDialog.tsx is the new presentation surface. It reuses useReactionsList, REACTION_OPTIONS, ReactionIcon, and ProfileAvatar.
  • frontend/src/components/ReactionsListPopover.tsx is removed; do not retain a parallel list implementation.
  • Consumers include post, comment, and post-image reaction bars. Message reactions retain their existing behavior because the dialog target type does not include messages.

Constraints

MustMust not
  • Preserve existing reaction mutation endpoints and summary callbacks.
  • Use the shared reaction-list hook and option definitions.
  • Provide an accessible modal name, Escape dismissal, visible close control, and backdrop dismissal.
  • Reset the selected filter and hook state when closed.
  • Prevent background scrolling only while the dialog is open.
  • No API, schema, or reaction-counting change.
  • No new dependency or second reaction-list abstraction.
  • No change to message-reaction flows.

Risk & blast radius

Level 2 — Concern. This moves a shared interaction from a locally positioned popover to a portal modal. Incorrect cleanup can trap the page in a scroll-locked state, while incorrect dismissal behavior can lose the current interaction. Mitigation: centralize close cleanup in the dialog effect, retain the existing hook contract, and verify post, comment, and post-image surfaces at desktop and mobile widths.

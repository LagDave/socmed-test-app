Graceful fallback for unavailable profile photos

Plan folder: plans/08182026-avatar-fallback
Planning branch: codex/plan-08182026-avatar-fallback
Execution branch: kylie/avatar-fallback → dev

Why

A non-empty but unavailable avatarUrl causes the browser’s broken-image glyph to appear in the inbox. A photo retrieval failure should preserve a polished, recognizable profile marker instead.

What

Enhance the shared ProfileAvatar component so an image-load error replaces the failed photo with its existing letter-based avatar fallback. Preserve the current size, shape, border, shadow, and empty alt text for valid images; use the same current display-name initial, styling, and hidden-from-assistive-tech semantics for the fallback.

Done when: an invalid or missing avatar resource never leaves a broken-image glyph, valid photos remain unchanged, and every existing consumer gets the fallback through the shared component.

Context

  • frontend/src/components/ProfileAvatar.tsx is the sole shared renderer. It currently renders an <img> whenever avatarUrl is non-null, without an error handler; its null-url path already contains the desired initial fallback.
  • ConversationListRow.tsx uses the component for the inbox profile photo shown in the reported screenshot.
  • The same component is reused by messenger thread/header/bubbles/composer/status, Friends, Notifications, feed/comment/share composers, the navbar/profile menu, profile dialogs, and profile pages. A component-level repair avoids duplicate consumer logic.
  • Invalid stored external URLs may still exist. Correcting URL persistence and migrating existing profile data are explicitly not part of this visual resilience fix.

Constraints

MustMust not
  • Fall back only after the browser reports an image-load failure.
  • Reset/avoid stale failure state when a component receives a different avatar URL.
  • Reuse the existing initial fallback presentation and preserve valid-image output.
  • Keep this client-only and dependency-free.
  • No backend, API, database, upload, or profile-URL normalization changes.
  • No change to the user’s saved avatar URL as a side effect of rendering.
  • No new avatar component or per-consumer fallback branches.
  • No modification to unrelated image renderers.

Risk & blast radius

Level 2 — Concern. ProfileAvatar is a shared primitive across major signed-in surfaces. An incorrectly scoped error state could hide a newly valid image after navigation or apply a fallback before the load fails. Mitigation: key failure state to the exact source URL and branch only after onError; verify both a failed inbox photo and a valid photo, plus one second shared consumer.

Why

Plan 15 put reactions under the post but deferred “Comment beside reaction.” Today the only feed path into comments is clicking the post body. Users want a Facebook-style action row: react and open comments side-by-side, with icons instead of the words “Comment” / “Reply.”

What

  • On Feed and post detail, place a comment icon immediately beside the post ReactionBar (same horizontal action row as the mock: reaction control → comment icon).
  • No visible “Comment” word for that affordance — lucide MessageCircle with aria-label="Comments" (or equivalent). No comment count in this plan (mock is icon-only).
  • Flip entry: clicking the comment icon navigates to /posts/:id#comments (same destination/process as today’s post-body link). Post body and image are no longer links to detail.
  • On post detail, the same comment icon beside post reactions scrolls to the comments section (#comments).
  • Under each parent comment, rearrange the action row to ReactionBar | Reply icon. Replace the text “Reply” button with lucide Reply (or CornerDownRight) + aria-label="Reply". Reply flow unchanged (one-level, inline composer, same submit API).
  • Keep compose submit button labels as text (“Comment” / “Reply”).

Done when: Feed and detail show reaction + comment icon side-by-side; comment icon opens/scrolls to comments; post body is not the detail entry; parent comments use a reply icon beside reactions; reply still works; typecheck/build green; acceptance checklist runnable.

Context

Today (kylie/friends-messenger tip):

  • FeedPage — post body is <Link to={`/posts/${p.id}`}>; ReactionBar sits alone under the post; no comment control.
  • PostDetailPage — ReactionBar under post; “Comments” heading + threads; text ghost Reply beside Delete; bottom form submit “Comment”; reply form submit “Reply”.
  • ReactionBar — self-contained flex row (trigger + counts). Action-row sibling must wrap ReactionBar + icon in a shared flex container — do not fork reaction logic into pages.
  • Icons already in app via lucide-react (MessageCircle used on Friends / Messages / Profile). Pattern: ghost icon button, h-4 w-4, aria-label (see ThemeToggle / Friends rows).

Closest analogs:

  • Layout target → user mock mock-action-row.png
  • Icon button chrome → ThemeToggle / Friends MessageCircle ghost buttons
  • Optional thin wrapper → new PostActionRow.tsx only if it avoids duplicating Feed + detail markup; otherwise inline flex next to existing ReactionBar is fine

Plan 15 deferred this explicitly (“No moving Comment into the reaction row”) — this plan is that follow-up.

Constraints

Must

  • Action row under post (Feed + detail): ReactionBar then comment icon, left-aligned, matching mock spacing
  • Comment affordance is an icon only (no “Comment” text label on the control)
  • Feed comment icon → /posts/:id#comments; detail comment icon → scroll/focus comments section with id="comments"
  • Remove post-body (and image) navigation to detail on Feed — flip entry to the icon
  • Parent-comment row: reactions + reply icon; remove text “Reply” button; startReply behavior unchanged
  • Keep Delete placement usable (icon row must not bury Delete); Delete may stay as text ghost near author chrome
  • Reuse lucide; no new npm deps
  • Frontend only — no schema, routes, or commentCount API
  • Follow Code Constitution; no business logic in UI beyond existing page patterns

Must Not

  • No comment count badge in this plan
  • No changing reaction picker / emoji set / ReactionBar API contract beyond accepting a sibling in a flex row
  • No nested replies beyond existing one-level model
  • No icon-only submit buttons on compose forms
  • No inline expand of comments on the Feed (still full detail page)
  • No backend / migration changes

Out Of Scope

  • Comment counts on feed payloads
  • Share button / who-reacted
  • Redesigning comment card chrome beyond the action-row rearrange
  • Messenger / friends surfaces

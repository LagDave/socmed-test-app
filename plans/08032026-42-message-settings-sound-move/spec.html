Why

Plan 34 shipped message notification sounds with the picker living on Account Settings. That made sense as a v1 stub, but sounds are a message preference — users expect them beside chat, not under account privacy/security. Account Settings should stay focused on identity, privacy, security, and account lifecycle stubs.

Plan 33 explicitly deferred a dedicated chat settings screen. This plan delivers that screen in minimal form: notification sounds first, with room for future message prefs without another navigation rethink.

What

Move the existing notification sound picker from Account Settings into a new Message settings page under the Messages area. Leave Account Settings with Privacy, Security, and More settings stubs only.

Deliverables:

Closest analogs

Route ordering note

Register /messages/settings before /messages/:conversationId in App.tsx so settings is not captured as a conversation id.

Constraints

Must

  • Relocate sound picker UI only — prefs keys and playback contract unchanged
  • Account settings retains Privacy, Security, More settings stubs
  • Message settings reachable from inbox without hunting through profile
  • Follow existing page rhythm (space-y-4, feed-card, B&W tokens)
  • Message settings page uses icon-only chrome — no text page title or subtitle
  • All icon controls accessible (aria-label, keyboard focus)

Must Not

  • No backend routes, services, or migrations
  • No refactor of notificationSounds.ts or sound assets
  • No new npm dependencies
  • No thread-header settings gear in this plan
  • No server-persisted message prefs

Out Of Scope

  • Activity/bell notification sounds (future plan)
  • Cross-device preference sync
  • Additional message settings (read receipts toggle, typing indicator prefs, etc.)
  • Renaming NotificationSoundsSettings component
  • Navbar link to message settings

Risk

Level 1 — Suggestion. Pure UI relocation with no data or playback changes. Blast radius is limited to settings navigation surfaces.

Required pushback: Do not bundle backend user-prefs API “while we’re here.” Do not merge message settings into ChatThemePicker modal — different scope (global vs per-conversation).

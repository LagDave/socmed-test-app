Why

Incoming photo messages currently render their action toolbar in the same horizontal row as the image. On a photo-heavy message, that separates the controls from the message group and consumes space beside the media. The result in the supplied reference is an oversized-looking image with reaction, reply, and overflow controls floating at its midpoint.

What

Make photo-bearing messages read as one compact message unit: avatar, optional text caption, and media stay on the sender’s message rail; the media follows the same maximum inline width as the rail; and the action toolbar is placed below the photo/caption on hover or touch reveal. Text-only messages retain their present side-toolbar layout.

Done when: incoming and outgoing photos stay aligned with their own message group, their controls never occupy the image’s side, captions remain attached to the photo, and the next message starts with normal thread spacing.

Context and closest patterns

  • frontend/src/components/MessageBubbleRow.tsx owns the message avatar, media, bubble, action toolbar, reaction badge, timestamp, and image lightbox trigger. Its shared flex … items-center content row is the direct cause of the side-mounted toolbar.
  • frontend/src/components/messages/ThreadViewContent.tsx is the live thread renderer. It supplies grouping, avatar, hover/touch, reaction, reply, edit, pin, and error props to MessageBubbleRow.
  • frontend/src/index.css owns thread item spacing, media-bubble helpers, reaction badge placement, and toolbar stacking. It is the closest pattern for named, reusable presentation constraints.
  • frontend/src/components/ViewChatImageDialog.tsx is the existing full-size image experience and remains the destination for photo clicks.

Scope and constraints

Must

  • Keep avatar, text caption, image, reaction badge, timestamp, and toolbar associated with the same message and sender side.
  • Give photo-bearing messages a vertical content/action layout; preserve the existing hover and touch-reveal behavior and accessibility labels.
  • Use one named media-size rule, bounded by the established message-content rail, so photos cannot widen into action space or the next message.
  • Preserve image-only rounded corners, mixed text-and-image bubble treatment, custom chat themes, reaction badges, and the lightbox.

Must not

  • No changes to message body rendering, sanitization, uploads, image API data, database schema, or message delivery.
  • No changes to text-only bubble geometry, reaction behavior, reply/edit/pin/unsend semantics, or conversation grouping rules.
  • No dependency, route, or theme-system changes.

Out of scope

Image cropping controls, multi-image albums, captions as a separate message type, media compression, and redesigning the image lightbox.

Required pushback — Level 2: Moving actions out from beside the image changes how quickly desktop users discover them. The mitigation is to retain the current hover/focus/touch reveal rules and verify both hover and non-hover paths; adding permanently visible controls would make narrow photo messages crowded and is not recommended.

Why

Opening a photo received in a conversation currently renders a wide, white modal with a titled header and padded media region. Portrait images fill most of the viewport while the surrounding frame dominates the screen. The viewer should instead make the image feel like a compact, floating object centered over the conversation.

What

Restyle the chat-photo viewer as an image-first lightbox: remove the visible “Image preview” header and all modal-panel/media padding; remove the opaque dialog frame; center the image within the viewport; and cap displayed media at 70vh and 24rem wide. Keep a compact Close action overlaid at the image’s upper-right edge.

Done when: portrait and landscape chat photos open centered with no broad white frame or surrounding in-modal padding; the image remains smaller than the prior 3xl-wide layout; consecutive image messages retain clear row spacing; and all existing dismissal and keyboard behavior works.

Context and closest patterns

  • frontend/src/components/ViewChatImageDialog.tsx is the only received-chat-image viewer and the sole implementation target. It owns the dialog markup, focus-on-open behavior, Escape handling, click-away dismiss button, and body scroll lock.
  • frontend/src/components/MessageBubbleRow.tsx is the only confirmed consumer. It passes the message image URL and owns the lightbox open state; its message rendering and interaction handlers are out of scope.
  • frontend/src/components/ViewCoverPhotoDialog.tsx is the closest existing image viewer for responsive object containment, although it intentionally retains a titled panel and is not a styling template for this compact chat viewer.
  • frontend/src/index.css defines shared .modal-backdrop, .modal-panel, and modal animation styles used by several unrelated dialogs. Those shared selectors must not change.

Scope and decisions

Must

  • Remove the visible “Image preview” heading, header border, and padded image container.
  • Make the dialog frame transparent and content-sized rather than a full-width max-w-3xl panel.
  • Center the image and preserve responsive containment with a maximum of 70vh height and 24rem width.
  • Keep the compact negative-margin treatment limited to consecutive text messages; image messages must retain normal row spacing.
  • Use a black, blurred backdrop for the chat-photo viewer in global or Messages dark mode.
  • Place a visible Close action as an overlay near the image, with a pointer and keyboard-accessible target.
  • Retain click-away dismissal, Escape dismissal, focus-on-open, modal semantics, and body scroll restoration.

Must not

  • Do not alter shared .modal-panel, .modal-backdrop, or animation CSS used by other dialogs.
  • Do not change message image upload, message-bubble layout, image URL data, or the open-state contract in MessageBubbleRow.
  • Do not add a dependency, create a second dialog system, or change the close behavior’s callback contract.

Out of scope: click-to-zoom, continuous pinch/wheel zoom, panning, image download, image metadata, gallery navigation, and visual changes to cover-photo or profile-picture viewers.

Required pushback — Level 2: removing the visible heading must not leave the dialog unnamed to assistive technology. The implementation must replace aria-labelledby with an equivalent static aria-label (for example, “Chat image”), keeping the user-requested absence of visible “Image preview” text without weakening modal semantics.

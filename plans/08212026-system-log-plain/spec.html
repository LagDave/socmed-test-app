Why

The supplied chat screenshot shows theme-change system entries rendered as rounded, tinted pills while existing pin and unpin activity is plain centered text. The requested conversation style is consistent, plain system logs without the bubble-like pill treatment.

What

Make every entry rendered through the shared MessageSystemLog component and every MessageDaySeparator date label visually plain: centered muted text with no rounded shape, filled background, border, or separate pill padding. Date/timestamp labels use bold text to retain their visual hierarchy; system and pin activity remain at the existing regular weight. Theme-change history and its date labels remain in the same chronological timeline position; system-log screen-reader status semantics remain intact; all plain labels stay readable in default and selected custom chat themes.

Done when: historical and newly-created theme-change entries and date/timestamp labels render as plain text; pin and unpin activity remains visually and behaviorally unchanged; no system log or date label gains a bubble or shaded background in either default or custom chat themes.

Context and blast radius

File / consumerRole and impact

Constraints / out of scope

  • Change visual presentation only; do not alter system-log text, actor names, timestamps, timeline sorting, day-separator rules, requests, socket events, or stored theme history.
  • Use the existing shared system-log component and stylesheet; do not introduce a dependency, migration, new activity data model, or a second system-log abstraction.
  • Keep role="status" on the system-log content and retain centered readable text. Date labels remain present but use the same plain visual language.
  • Pin/unpin entries are the visual reference and remain unchanged. Day separators are timestamp labels in scope for this continuation; only their pill treatment changes.
  • Follow Code Constitution §§2.1 and 4.3: presentation belongs in the existing frontend component/CSS owners; no backend or business-logic changes are permitted.

Risk and mitigation

Level 2 — Concern. Removing the filled background means system-log legibility depends entirely on the muted foreground against each chat-theme background. The blast radius is every conversation that has retained theme-change history, including solid and gradient themes. Mitigation: retain the existing custom-theme muted color token, remove only the pill geometry/background, and visually verify default, solid, and gradient theme threads at desktop and narrow widths.

Chat timestamp reduction

Plan folder: plans/08082026-49-chat-timestamp-reduce · Execution branch: kylie/chat-timestamp-reduce → dev · Risk: Level 2.

Why

Message gaps of ten minutes already receive a separator, but its full date-and-time text (for example, Aug 7, 2026, 9:18 PM) is visually heavy. The desired chat reading is a compact time such as 9:18 PM.

What / success criteria

  • Keep the existing ten-minute message-gap rule unchanged.
  • Render a qualifying gap separator as a local, time-only label with an hour and two-digit minutes (for example, 9:18 PM in a 12-hour locale).
  • Keep current calendar-day separators (Today, Yesterday, or a date) and all message grouping behavior unchanged.

Context

  • frontend/src/lib/formatMessageDay.ts owns the named 10-minute threshold via messagesHaveTimeGap; it is the source of truth for whether the separator appears.
  • frontend/src/lib/formatRelativeTime.ts owns formatMessageTimeSeparator; it currently formats the date and time and is the sole formatting change.
  • frontend/src/components/messages/ThreadViewContent.tsx is the only timeline consumer: it renders the formatter only when the gap condition is true and no new calendar day begins.
  • Closest existing formatting pattern: formatAbsoluteTime in the same time-formatting module handles invalid dates before localized browser formatting.

Constraints / out of scope

  • Must not alter the 10-minute threshold, message ordering, grouping, day-separator rules, API payloads, database schema, or realtime behavior.
  • Must retain the current invalid-date behavior (empty label).
  • Must use browser-local formatting; the screenshot’s 9:18 PM is the expected 12-hour-locale presentation.
  • Out of scope: relative timestamps on posts, comments, inbox rows, search results, and per-message timestamps revealed on click.

Risk and mitigation — Level 2

Timestamp presentation is shared user-facing behavior: an over-broad formatter change could alter feed or comment labels, while changing the gap predicate would unexpectedly regroup messages. Limit the implementation to formatMessageTimeSeparator, confirm its sole consumer, and behaviorally verify just-below and at-threshold gaps. No persistence or server consumers are in the blast radius.

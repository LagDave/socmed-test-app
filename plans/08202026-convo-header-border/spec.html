Remove the conversation-header divider

Plan folder
plans/08202026-convo-header-border

kylie/convo-header-fix

dev
Size
Small · 2 tasks · 1 app file
Risk
Level 1 · suggestion

Why

The supplied conversation screenshot shows a visible horizontal rule separating the profile/action header from the message pane. It makes the header read as a distinct bordered panel; the requested visual is a continuous conversation surface without that divider.

What

Remove the bottom divider produced by .messages-thread-header::after and eliminate the card-like seam beneath a custom-themed header. A custom chat background must be painted once by the thread container, with transparent header and pane children over it, so a gradient does not restart at the header boundary. The header keeps its sticky position, padding, accessibility, profile link, and all action controls. The small border surrounding the Search/Palette/More action cluster is explicitly retained.

Done when: default and custom-chat-theme conversation headers have no bottom line or visible surface seam, while the rest of the thread header and composer separator remain unchanged.

Context and blast radius

File / consumerRole and impact
frontend/src/index.cssOwns the divider source and thread theme selectors. It will make the default header match the thread pane and paint an active custom theme once on the outer thread container.
frontend/src/components/messages/ThreadViewContent.tsxThe only live renderer of messages-thread-header, used at /messages/:conversationId. It currently applies the active theme background to the pane; that local paint must move to the outer container so the gradient remains continuous.
Default and selected chat themesBoth render the shared header selector. Custom gradients currently restart in the header and pane independently, creating the screenshot’s visible seam; both states require acceptance verification.
frontend/src/components/messages/ConversationThreadHeader.tsxUnused legacy header component. It is not a consumer of messages-thread-header and is out of scope.

Constraints / out of scope

  • Remove the header-to-thread divider and the custom-gradient seam only; retain the action-cluster border, avatar outline, and composer top separator.
  • Do not alter header structure, interaction handlers, theme data, routes, APIs, state, or persistence.
  • Use the existing Messages stylesheet; no new dependency, component, migration, or generalized chat-style refactor.
  • Follow Code Constitution §§2.1 and 4.3 by keeping this visual concern in its existing CSS owner, and §§13.3 and 17.2 by leaving the React component and its typing unchanged.

Risk and mitigation

Level 2 — Concern. Moving the custom background to the outer thread container changes which element paints the theme. Its blast radius is every selected chat theme, including gradients and scrollable pane content. Mitigation: preserve the existing CSS variables and message color rules, keep the default surface unchanged except for matching its header/pane background, and verify solid and gradient themes at desktop and narrow widths before finalization.

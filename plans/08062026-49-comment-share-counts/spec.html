Show comment and share action counts

Why

The post action row did not expose the amount of discussion or resharing before a user opened either flow. Feed and detail payloads need efficient aggregate counts, and the action controls need readable visual and accessible labels without turning each post into separate count queries.

What

Add commentCount and shareCount to the server and frontend PostView contracts. Hydrate them in batches for the currently loaded posts, then render positive counts beside the comment and share actions, capping visual output at 99+ while retaining the full number in the accessible label.

Done when: post-level comments and direct shares are counted correctly across a feed batch; zero counts remain unobtrusive; visible counts and assistive labels agree; and existing share/comment actions remain functional.

Context

  • src/services/PostService.ts centralizes post-view hydration. It now loads authors, reaction summaries, comment counts, and share counts concurrently before constructing views.
  • src/models/CommentModel.ts groups comment counts by post_id and deliberately excludes image comments (post_image_id IS NULL).
  • src/models/PostModel.ts groups direct shares by shared_from_post_id.
  • frontend/src/api/types.ts mirrors the new response fields; PostCard, SharedPostEmbed, and feed/detail consumers pass them to PostActionRow.
  • frontend/src/components/PostActionRow.tsx is the only action-count presentation surface; preserve that single abstraction.

Constraints

MustMust not
  • Batch aggregate counts by the current post IDs; return zero for posts with no matching rows.
  • Count post-level comments only, excluding comments attached to an individual post image.
  • Count direct posts that reference the source post as a share.
  • Render positive counts inline and expose the full count in each control’s accessible label.
  • Use one shared action-row count component for post-card and embedded-post consumers.
  • No per-post query loop (N+1).
  • No duplicated count formatting or parallel frontend action control.
  • No schema migration or new dependency.
  • No silent inclusion of photo comments in the post discussion count.

Risk & pushback

Level 2 — Concern. The hydration path serves feed and detail views; an aggregate query in the mapping loop would create an N+1 performance regression, and ambiguous counting semantics would make the displayed discussion count misleading. Mitigation: use two grouped batch queries keyed by post ID, seed defaults for every requested post, and acceptance-test post-level comments (including replies), image comments, zero counts, and shares.

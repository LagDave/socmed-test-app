Give the message options menu a floating caret

Plan: plans/08082026-pin-message-arrow
Execution branch: kylie/pin-message-arrow → dev
Planning branch: plan/08082026-pin-message-arrow

Why

The message “Pin message” menu is portal-positioned and therefore already floats over the conversation, but it has no visual connection to its three-dot trigger. Add the small popover caret shown in the supplied reference so the menu visibly belongs to the active message action.

What

Expose the existing Radix dropdown-arrow primitive through the shared dropdown wrapper, then render it only in the message action menu. The normal placement changes from beside the action toolbar to directly above the three-dot Message options trigger. Keep the menu floating in the portal and allow its bottom-edge caret to remain visibly connected to the rounded menu surface, with no exposed background seam or gap. The caret’s point must be horizontally aligned with the trigger, as in the supplied reference; when collision handling flips the menu, it must move to the corresponding trigger-facing edge rather than becoming detached or clipped. Keep the three-dot trigger visible while the portal menu owns focus, so the bottom notch remains visibly anchored. The pin action is text-only; remove its current pin/unpin icon.

Done when: opening a message’s options exposes a rounded floating menu above a still-visible three-dot action, with a visibly continuous, color-matched bottom notch pointing straight down at it and a text-only Pin/Unpin action; Pin/Unpin, Edit, and Unsend retain their current permissions and actions; the menu remains correctly positioned near every viewport edge; and non-message dropdowns remain visually unchanged.

Context

  • frontend/src/components/MessageBubbleRow.tsx owns the per-message action toolbar and is the sole message options-menu consumer.
  • frontend/src/components/ui/dropdown-menu.tsx wraps Radix Dropdown Menu content in a portal and currently clips child overflow for its rounded surface.
  • frontend/src/components/messages/ThreadViewContent.tsx owns the overflow-hidden thread card; because the dropdown uses a portal, it must not be changed for this visual adjustment.
  • Other shared-wrapper consumers are the inbox row, conversation header, thread header, navbar, and pinned-message header. They must retain their existing no-caret appearance.

Constraints

MustMust not
  • Use the existing Radix dropdown primitive; no positioning dependency or custom document-level placement code.
  • Keep the dropdown portal and collision behavior intact.
  • Match the menu’s popover/background and border treatment, with the caret visibly outside the rounded menu body.
  • Preserve current keyboard focus, Escape, pointer dismissal, menu-item semantics, and disabled pin-save behavior.
  • No API, pinning-state, permission, or message action behavior change.
  • No pin or unpin icon in this menu; the action text remains its accessible name.
  • No change to shared menu appearance unless that consumer explicitly renders the new arrow.
  • No change to the thread-card overflow rules or unrelated message styling.
  • No new dependency.

Risk & blast radius

Level 2 — Concern. A globally rendered caret or an unchanged overflow-hidden menu surface would either alter unrelated menus or clip the new visual. Changing the normal placement from side-aligned to above-trigger also risks overlap with nearby messages or a caret that misses its trigger. Mitigation: export only the primitive wrapper, opt in at the message menu, use Radix top/center placement with collision fallback, give that menu a non-clipping outer surface with a nested rounded body where needed, and verify the pointer’s alignment and every collision side.

Why

1:1 chat is a flat chronological thread. When a friend sends something you want to respond to specifically, there is no way to anchor your reply to that message. Messenger-style quote replies fix context drift in busy threads — you tap a message, see a preview in the composer, send, and the reply bubble embeds the quoted original.

What

  • Hover/focus on any non-unsent message (yours or theirs) reveals a Reply control beside the existing react affordance.
  • Choosing Reply sets composer state: a preview bar above the thread textarea shows the quoted sender name + truncated body and/or a small image thumb + Cancel.
  • Submit sends a normal new message with optional replyToMessageId; the thread stays flat (no nesting).
  • Reply bubbles render a quote strip above the reply body — sender name + truncated original text or image thumb; unsent originals show Message unavailable.
  • Socket + REST list/create responses include embedded replyTo so quotes work even when the original is not in the loaded page window.
Thread (flat order preserved):

  Friend:  "Are we still on for Saturday?"
  You:     ┌ quoted strip ─────────────────────┐
           │ Friend · Are we still on for…       │
           └─────────────────────────────────────┘
           "Yes! See you at 2."

Composer while replying:
┌─ reply preview bar ────────────────────────────┐
│ Replying to Friend · Are we still on for…  [×] │
└────────────────────────────────────────────────┘
[ textarea … ]                          [ Send ]

Context

Today:

  • messages table — body, image_url, unsent_at; no reply FK (database/migrations/20260729140000_friends_messenger.ts).
  • MessageService.send accepts { body?, imageUrl? }; MessageView has no reply fields.
  • MessageBubbleRow — bubble + hover react + unsend menu; no reply trigger or quote UI.
  • MessagesPage ThreadView — inline footer composer (textarea + image attach); reply state lives here.
  • Realtime — message:new carries full MessageView; no new event needed once view includes replyTo.

Closest analog: post comment replies use parentId + CommentComposer “Replying to {name}” banner — reuse the composer-banner pattern but add snippet/thumb and in-bubble quote rendering (Messenger, not indented comment threads).

Constraints

Must

  • Add nullable reply_to_message_id UUID REFERENCES messages(id) ON DELETE SET NULL on messages
  • sendMessageSchema accepts optional replyToMessageId UUID; when set, target must exist, belong to same conversation, and unsent_at IS NULL at send time
  • MessageView.replyTo: { id, senderId, senderDisplayName, body, imageUrl, isUnsent } | null — hydrated via join on list/create/socket (live unsent state)
  • Quote strip inside bubble; composer preview bar with Cancel; clear reply state on send, cancel, and conversation change
  • Reply control hidden on unsent messages
  • Auth unchanged — participants only
  • No new npm dependencies

Must Not

  • Nested/indented thread UI (comment-style tree)
  • Modal reply composer
  • Notifications for replies
  • Denormalized quote snapshot columns (join is enough for v1)
  • Scroll-to-original on quote tap (deferred)

Out Of Scope

  • Swipe-to-reply (mobile gesture)
  • Forward message
  • Edit reply / edit quote
  • Reply from inbox list (thread-only)
  • Tap quote → scroll to original (deferred to post-v1)

Risk

Level 2 — Concern. Schema + API contract change on a live messaging path; quote rendering depends on join correctness and unsent edge cases.

HazardBlast radiusMitigation
Invalid reply target (wrong conversation / unsent) Broken references, confusing UI Service validates before insert; 4xx on bad replyToMessageId
Original unsent after reply sent Stale quote text Join at read time; replyTo.isUnsent → “Message unavailable” strip
Quoted message not in loaded window Missing quote in bubble Always embed replyTo on API/socket payloads — never client lookup by id alone
Composer state leak Next send wrongly quotes prior message Clear replyTo on success, cancel, and conversationId change
N+1 on message list Slower thread load Single query with left join to parent message + sender display name (or batched parent fetch)

Consumers: MessageModel, MessageService, ConversationModel (inbox last message), MessageRealtime, MessagesController, FE MessageView, MessageBubbleRow, MessagesPage, migration.

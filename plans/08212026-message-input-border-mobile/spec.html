Message composer: remove duplicate border and use a Messenger-style mobile layout

Plan folder: plans/08212026-message-input-border-mobile · Execution branch: kylie/input-border → dev · Planning branch: codex/plan-08212026-message-input-border-mobile · Risk: Level 2

Why

The supplied conversation screenshot shows two competing boundaries at the composer: a top divider/elevation on the form and an outlined inner composer track. On a phone, the current avatar-and-card treatment consumes useful horizontal space and does not read like a native Messenger composer.

What / acceptance target

Remove both competing composer boundaries on desktop: the form-level divider/elevation and the outlined inner composer track identified in the screenshot. Use a compact desktop row (32px avatar, send control, and textarea minimum with reduced vertical padding) rather than the current chunky treatment. Give the desktop textarea its own soft rounded composer pill, while the Send arrow remains an icon-only ghost control with no resting filled card. In active chat themes, let the thread and composer share one parent conversation canvas rather than tinting the footer separately. At the existing mobile breakpoint (640px and below), render a compact, Messenger-style footer: no self avatar or outer card/divider; attachment and emoji actions beside one soft rounded text-input pill; and the existing send action at its trailing edge. The reply/edit previews, image upload, emoji insertion, keyboard sending, typing indicator, disabled state, and active chat-theme contrast must remain functional.

This is a presentation-only change. No API, realtime event, database, dependency, navigation, or message-state behavior changes are in scope.

Context and existing pattern

  • frontend/src/components/messages/ThreadViewContent.tsx is the live conversation composer. It currently applies the form divider/shadow, renders the self avatar, attachment/emoji controls, textarea, and send button. The similarly named ConversationComposer.tsx has no consumer and is expressly out of scope.
  • frontend/src/index.css owns .messages-composer-track and all theme overrides for the composer. It is the closest styling analog and the correct location for responsive presentation rules.
  • The existing @media (max-width: 640px) convention in frontend/src/index.css is the breakpoint to extend. Preserve CSS custom-property based theme colors so chat themes do not receive a parallel visual system.
  • Applicable Constitution guidance: §13.1 (file-size ceiling), §13.3 (component responsibility), §4.3 (careful DRY), §17.2 (no any), §20.3 (no skipped tests), and §20.5 (acceptance artifact).

Risk and mitigation

Level 2 — shared composer states and theme variants. This view serves normal, dark, and active custom-chat themes plus edit and reply modes. A mobile-only structural change can break narrow layouts or reduce contrast. Mitigation: keep all event handlers, ARIA labels, and button semantics intact; use the existing theme variables rather than hard-coded colors; exercise normal, reply, edit, and themed cases at desktop and phone widths. Blast radius is limited to the conversation thread composer; inbox compose, comments, and feed composers are excluded.

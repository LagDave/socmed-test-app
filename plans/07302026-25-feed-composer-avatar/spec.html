Why

The signed-in Feed still opens with a page title block (“Feed” / “You and your mutuals.”) above a full-width composer. That reads like a document header, not a social post box. Users expect a Facebook-style strip: your face on the left, the “What’s on your mind?” field inline beside it.

What

  • Remove the Feed page header block entirely (title + “You and your mutuals.”).
  • Composer top row becomes Facebook-style:
┌─ feed-card ──────────────────────────────────────────┐
│  (● avatar)   What's on your mind?          [ Post ] │
└──────────────────────────────────────────────────────┘
  • Left: mini circular avatar from the signed-in user’s profile (user.avatarUrl), with letter fallback when null.
  • Middle: “What’s on your mind?” textarea filling the remaining width.
  • Right (same row): Post button — no second row, no divider line under the composer.
  • Avatar is a link to the current user’s profile (/u/{username|me}) — same target pattern as AppShell Profile nav.
  • No Feed composer file picker (Rev 2); posts created from Feed send imageUrl: null.
  • Feed post cards (Rev 8–9): author sm avatar beside name; tighter body spacing; single soft divider above react/comment; more gap between composer and first post.
  • Signed-out landing unchanged.

Done when: no Feed/subtitle header; one composer row = avatar + prompt + Post; shared ProfileAvatar; post cards use avatar + soft action divider; typecheck/build green; acceptance Passed.

Constraints

Must

  • Remove Feed title + subtitle from the signed-in Feed view
  • Single composer row: sm circular avatar left + “What’s on your mind?” middle + Post far right
  • No second action row and no divider line under the composer
  • No Feed composer file input
  • Avatar uses authenticated user.avatarUrl / displayName fallback; updates when auth user updates (no extra fetch)
  • Avatar links to own profile
  • Share one circular avatar implementation (ProfileAvatar extracted or equivalent shared module) with a new sm size (~40px)
  • Preserve compose API behavior, Enter-to-submit, validation, busy/error handling
  • Frontend only — no schema, routes, or payload changes

Must Not

  • No modal / popup composer
  • No separate Post row / border divider under the composer (Rev 3)
  • No Choose File / image attach control on the Feed composer (Rev 2)
  • No dual hairline sandwich on post cards (Rev 8 — one soft divider above actions only)
  • No changing Profile page avatar sizes except wiring to the shared component
  • No backend / migration changes
  • No new dependencies

Out Of Scope

  • Avatars on comments / replies
  • Navbar avatar
  • Post detail page card layout parity (Feed-only card polish)
  • Re-adding image attach to Feed composer (removed in Rev 2)
  • Composer photo preview / media picker redesign
  • Signed-out marketing copy

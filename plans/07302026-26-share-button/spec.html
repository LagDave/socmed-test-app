Why

Feed and post detail already have react + comment icons on one action row. There is no way to amplify a friend’s post onto your own feed. When you’re proud of a friend’s text or photo post, Facebook-style reshare is the missing control — one icon, same row, content-aware embed (text and/or image from the original).

What

  • Add a lucide Share2 icon button beside the comment icon on PostActionRow (Feed + Post detail).
  • Share is Facebook-style reshare to your feed: creates a new post authored by you that references the friend’s original post.
  • Share appears only on other people’s original posts (not your own; not on share-wrapper posts).
  • Shared feed card shows attribution + nested original (body and/or image as the original has).
  • One-click share — no commentary modal in this plan.
Action row (friend’s original post):
[ ReactionBar ] [ Comment ] [ Share2 ]

Shared card on your feed:
┌─ feed-card ─────────────────────────────────────────┐
│  (you)  You shared Alex’s post            · 2m      │
│  ┌─ nested original ──────────────────────────────┐ │
│  │  (Alex)  Alex @alex                            │ │
│  │  original body text…                           │ │
│  │  [optional image]                              │ │
│  └────────────────────────────────────────────────┘ │
│  ─────────────────────────────────────────────────  │
│  [ ReactionBar ] [ Comment ]          ← no Share    │
└─────────────────────────────────────────────────────┘

Context

Today (on kylie/feed-profile tip 2d04bb8 — planning base):

  • frontend/src/components/PostActionRow.tsx — flex row: children (ReactionBar) + MessageSquare comment control. Natural home for Share2 after comment.
  • FeedPage / PostDetailPage both wrap ReactionBar in PostActionRow.
  • posts table: id, author_id, body, image_url, timestamps — no share column. Create schema requires body.min(1).
  • FriendshipModel.areFriends exists for mutual-accepted checks.
  • Feed already lists self + mutuals; “friend’s post” ≈ author.id !== viewer.id among feed items that are not share wrappers.

Execution precondition (required): Kylie/share-button was created from ancient main (7ebfbd4) and does not contain PostActionRow / modern Feed. Before any app edits, hard-reset onto kylie/feed-profile tip so the action row exists.

Closest analog: comment icon in PostActionRow (icon ghost button + aria-label); nested content pattern ≈ existing post body + optional imageUrl block; FK-nullable parent pattern ≈ comments.parent_id.

Constraints

Must

  • Share2 icon only — no “Share” text label
  • Same action row, immediately after the comment control
  • Show Share only when viewer ≠ post author AND post is not itself a share (sharedFromPostId == null)
  • Persist shares with posts.shared_from_post_id → posts(id), ON DELETE SET NULL
  • Share wrapper may have empty body and null image_url; content comes from the nested original
  • Hydrate sharedFrom: PostView | null on PostView (null if original gone)
  • Nested embed renders original author + body and/or image
  • Backend rejects sharing own post and sharing a share-wrapper; require mutual friendship with original author
  • Preserve existing compose / reactions / comments behavior

Must Not

  • No Web Share API / OS sheet / copy-link as the primary action
  • No commentary / “Say something about this” modal (v1)
  • No deep-copy of body/image into the wrapper row as the source of truth
  • No Share button on own posts or on share cards
  • No share-of-share chains in v1 (hide control on wrappers)
  • No new npm dependencies
  • No DM / Messages forwarding path

Out Of Scope

  • Optional share commentary / quote-share UI
  • Notifications to the original author
  • Share counts / “N shares”
  • Unshare (delete own share is enough via existing Delete)
  • Profile timeline reshare chrome beyond whatever feed cards already appear if profile lists posts later
  • Privacy beyond mutual-friends feed visibility

Risk

Level 2 — Concern. Primary hazards: executing on ancient tip; empty-body validation interacting with normal compose; N+1 when hydrating nested originals; share button leaking onto own posts.

Data & API

Migration

  • Add nullable shared_from_post_id uuid on posts, FK → posts(id) ON DELETE SET NULL, index on shared_from_post_id.
  • Idempotent hasColumn guard (match recent migration style).
  • Scaffold notes live in migrations/README.md; real Knex file under database/migrations/ at execute time.

PostView (BE + FE)

  • Add sharedFromPostId: string | null.
  • Add sharedFrom: PostView | null — nested original without further nesting required in v1 (sharedFrom.sharedFrom may be null/omitted; do not recursively embed chains).

Route

  • POST /api/posts/:id/share (auth) → creates wrapper post for req.userId, returns { post } 201.
  • Rules: original exists; original has no shared_from_post_id; author ≠ viewer; FriendshipModel.areFriends(viewer, author); wrapper body '', image_url null.

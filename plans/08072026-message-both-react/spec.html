Show both participants’ reactions on a message

Plan folder: plans/08072026-message-both-react
Execution branch: kylie/message-both-react → dev
Scope: Small frontend presentation fix (one component)

Why

Direct-message reaction persistence already permits one reaction from each participant. The message bubble chose only the viewer’s reaction or the first non-zero emoji, hiding the other participant’s reaction.

What

Render every emoji with a non-zero count in a compact reaction badge beneath the message bubble. Different reactions appear side by side; matching reactions render once with a count of 2. Existing picker, mutation, realtime, and persistence flows remain unchanged.

Done when: both participants can react independently and the conversation visibly represents both reactions without disturbing bubble geometry or message status.

Context

  • message_reactions already enforces one row per (message_id, user_id).
  • MessageReactionModel.summariesForMessages and the existing socket event provide counts for all reaction types.
  • frontend/src/components/MessageBubbleRow.tsx was the only implementation target: it collapsed the summary into one badge icon.

Constraints

MustMust not
  • Derive visible reactions from existing non-zero reactionSummary.counts in REACTION_OPTIONS order.
  • Show a count only when the reaction count is greater than one.
  • Preserve sent/received placement, image, grouping, themed bubble, timestamp, and delivery/seen-status spacing.
  • No API, database, model, service, controller, route, socket, or shared type change.
  • No who-reacted list, dialog, notification, dependency, or unrelated layout refactor.

Risk and blast radius

Level 2 — Concern. The bubble owns reaction clearance and delivery status. A larger badge could collide with surrounding UI. Mitigation: retain the existing anchored badge and clearance condition, changing only its inner content; test incoming/outgoing, image-only, grouped, themed, and seen-state messages in an isolated two-user runtime.

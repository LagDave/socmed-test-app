Remove the chat “Load earlier messages” button

Plan: plans/08062026-remove-load-earlier-button
Execution branch: kylie/remove-load-earlier-button → dev
Pull request: #70 — feat: auto-load earlier chat history

Why

Chat history pagination should be seamless. The manual “Load earlier messages” control duplicates the intended top-of-thread behavior and adds clutter. Grouped messages must also remain visually compact while meaningful time gaps stay understandable on every chat theme.

What and Done

  • Remove the visible manual load control from the active thread.
  • Load the next historical page automatically when the user reaches the top sentinel of the thread’s existing scroll container.
  • After selecting a search result, load the surrounding context and continue paginating toward both the older and newer ends of the conversation.
  • Preserve existing request guards, chronological merging, viewport preservation, and error behavior.
  • Keep consecutive incoming bubbles compact; show a centered absolute timestamp after any grouping-window time gap, independent of sender.
  • Keep timestamp contrast readable on themed chat surfaces, including pink.

Constraints

MustMust not / out of scope
  • Use the existing scroll pane as the observer root.
  • Respect hasMore, loadingThread, and loadingEarlier so no duplicate request starts.
  • Keep the existing error feedback and retry on a later top intersection.
  • Leave day separators authoritative at day boundaries and preserve reaction clearance.
  • No pagination API, socket, search, pin, reply, or composer change.
  • No message ordering or initial-load change.
  • No dormant-component cleanup or broad chat UI refactor.

Risk & blast radius

Level 2 — Concern. Removing only the button would make older pages unreachable because the active thread previously had no mounted top-sentinel observer. A duplicate observer could also trigger overlapping loads. Search focus adds the inverse risk: loading only the older context leaves the user trapped at the selected message. Mitigation: use independently guarded before/after cursors, retain chronological deduplication, and validate a multi-page conversation through both ends.

Consumers: /messages/:conversationId through ThreadView.tsx, ThreadViewContent.tsx, and useConversationSearchResultFocus.ts; the message-list controller, service, and model; themed thread styling in frontend/src/index.css.

Use a neutral icon before the viewer reacts

Why

The collapsed post reaction trigger currently renders the yellow Like sticker even when the viewer has not reacted. That makes an empty state look selected. It should instead begin as a neutral, outlined reaction affordance and switch to the selected reaction’s existing sticker after a successful reaction.

What

In the shared default reaction bar, render a muted outlined ThumbsUp icon while summary.viewerEmoji is null. When the viewer has reacted, preserve the existing selected sticker, picker interaction, mutations, summaries, and animations. The unreacted control’s accessible name becomes React; selected controls retain the named reaction label.

Done when: an unreacted post, comment, or post photo presents the neutral icon; selecting a reaction replaces it with that reaction’s sticker; selecting the same reaction again returns it to neutral; and message reaction toolbars remain unchanged.

Context

  • frontend/src/components/ReactionBar.tsx owns the collapsed trigger, picker timing, request mutation, and display state for posts, comments, post images, and messages.
  • The default variant is used by PostCard.tsx, CommentItem.tsx, and PostMediaGallery.tsx. Their empty states will intentionally be consistent.
  • The message toolbar variant already uses the neutral Smile icon and is explicitly out of scope.
  • lucide-react is already a frontend dependency and ThumbsUp matches the existing icon-button language. No asset or dependency is required.
  • ReactionIcon falls back to the Like sticker for a null emoji. It remains correct for rendered reaction values, but must not be used for this empty trigger.

Constraints

MustMust not
  • Use a compact outlined icon—not a loading skeleton—only for the known unreacted state.
  • Preserve all existing API endpoints, set/switch/clear behavior, hover/touch picker interaction, summary counts, and reaction stickers after selection.
  • Size the neutral icon appropriately for the existing md and sm default trigger tokens.
  • Keep the toolbar variant unchanged.
  • No backend, schema, route, or response-contract changes.
  • No new dependency, icon pack, image asset, or duplicate reaction-state implementation.
  • No direct edits to post, comment, post-photo, or message consumers unless required to fix a verified integration break.
  • No skeleton: loading is not the state being represented.

Risk & blast radius

Level 2 — Concern. ReactionBar is shared by three default content surfaces. A null fallback change can accidentally affect selected rendering, icon sizing, or screen-reader labels across all of them. Mitigation: branch explicitly on viewerEmoji only in the collapsed default trigger, preserve the existing ReactionIcon path for selected reactions, and validate set/switch/clear across each default consumer.

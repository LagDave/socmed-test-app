Why

Post detail shows comments and replies with no time signal. Feed posts use absolute toLocaleString() dates that are hard to scan. Users need a consistent, human-readable “how long ago” cue on feed posts, top-level comments, and replies.

What

  • Shared frontend helper that turns an ISO / Date-like createdAt into a relative English string (e.g. just now, 5 minutes ago, 2 hours ago, 3 days ago).
  • Feed: replace absolute toLocaleString() with the relative helper; keep existing right-aligned <time> placement.
  • Post detail: show the same relative timestamp right-aligned on the author row for top-level comments, replies, and orphan comments.
  • Each <time> uses dateTime (ISO) and a title with the absolute local datetime for precision on hover.

Done when: feed posts, parent comments, and replies all show relative times right-aligned; absolute value available via title; no live ticking interval; no new npm deps; frontend typecheck/build green.

Context

API already ships timestamps: CommentView.createdAt and PostView.createdAt are present (frontend/src/api/types.ts). Backend hydrate already maps created_at. No migration or API change.

Feed today: frontend/src/pages/FeedPage.tsx — author left, <time className="text-xs text-muted-foreground"> right via flex … justify-between, value = new Date(p.createdAt).toLocaleString().

Post detail today: frontend/src/pages/PostDetailPage.tsx — parent row is author/body left + Reply right; reply rows are author then body only. No <time>.

Closest analog: feed’s right-aligned <time> layout. Reuse that flex pattern on comment/reply author rows.

Lib home: frontend/src/lib/ already holds theme.ts / utils.ts — add a small formatRelativeTime.ts (or time.ts) beside them.

Branch base: feature branch must be cut/rebased from origin/dev (replies merged via PR #5). Planning worktree is already on that tip.

Constraints

Must

  • One shared formatter used by Feed + Post detail (no duplicated relative-time logic)
  • Relative English strings via Intl.RelativeTimeFormat (or equivalent native API) — no new packages
  • Right-aligned muted text-xs timestamps on feed posts, parent comments, and replies
  • Semantic <time dateTime={iso}> with absolute title
  • Apply on orphan comments too (same treatment as a flat comment row)
  • Compute once per render — no setInterval ticking

Must Not

  • No backend / migration / API contract changes
  • No new npm dependencies (no date-fns / dayjs / moment)
  • No live auto-refresh of relative labels
  • No drive-by reply/composer refactors

Out Of Scope

  • Locale switching / i18n beyond the browser default for Intl
  • Edited-at / “updated” timestamps
  • Profile page or other surfaces beyond feed + post detail comment thread
Decisions locked: relative format; right-aligned (Option B); both parents and replies; feed included; no live tick; base on origin/dev.

Relative format rules

Helper signature sketch: formatRelativeTime(iso: string | Date, now?: Date): string.

AgeDisplay
< 45 secondsjust now
< 60 minutesN minute(s) ago via Intl.RelativeTimeFormat
< 24 hoursN hour(s) ago
< 7 daysN day(s) ago
< 5 weeksN week(s) ago
< 12 monthsN month(s) ago
elseN year(s) ago

Use numeric: "auto" where it helps (“yesterday”) is fine; otherwise keep simple “N units ago”. Invalid dates → empty string or — (prefer empty; do not throw).

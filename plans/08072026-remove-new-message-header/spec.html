Socmed Plan Spec

Streamline the populated inbox composer

Status: Completed

Execution branch: kylie/message-ui → dev

Why

The populated inbox currently repeats one task through a header action row, a broad search control, and often a row of compose chips. It leaves a large, low-value block above the conversation list—and hiding the entry point entirely makes starting a message undiscoverable. The inbox needs one persistent, unambiguous New message action.

What / Done

  • When the inbox already has conversations, do not render the New message section heading.
  • Use the existing person-plus toolbar icon as an always-available New message action.
  • Show the populated-inbox picker only while that action’s searchable friend list is open; otherwise let the Conversations section follow directly.
  • Remove Manage friends from the Messages toolbar; it remains available on the Friends surface.
  • Keep search opening/closing, Escape handling, focus restoration, and friend selection behavior unchanged once the new-message action is used.
  • Keep the Friends heading for a new inbox with no conversations.
  • Pass frontend typecheck, lint, and production build; record the UI acceptance result.

Context

frontend/src/components/MessagesFriendPicker.tsx owns the friend-search rendering and selection behavior. frontend/src/components/messages/InboxView.tsx owns the toolbar, the compose container (and its spacing/divider), and the persistent action that controls whether the picker is open. The existing person-plus icon becomes that action; the settings icon remains unchanged.

Constraints / Out of scope

  • Modify only the picker and page-toolbar presentation/state wiring; do not change API calls, routes, friend selection, or shared CSS.
  • Do not remove the ability to manage friends; retain the Friends surface as its destination.
  • No new dependency, migration, test framework, or unrelated message UI refactor.

Risk

Level 1 — Suggestion. This is a local presentation and UI-state change. The blast radius is the populated inbox, including its picker loading and error states. Mitigation: keep the picker visible while open, loading, or errored; verify the person-plus action opens search for both new and existing conversations, and preserve the Friends empty-inbox state.

Why

PR #72 deliberately reverted its compact timestamp change because it was unrelated scope in a comment/share-count pull request. This dedicated feature restores that approved presentation rule at its single shared source, so every existing consumer changes consistently without touching their layouts or data contracts.

What

Update only formatRelativeTime in frontend/src/lib/formatRelativeTime.ts to restore PR #72’s compact strings: now, 8min, 4hr, 2d, 3w, 5mo, and 1yr. Retain the current bucket thresholds, rounding, invalid-date result, and no-ticker behavior. Future values keep the restored PR behavior: values below 45 seconds render now; later values retain an in prefix (for example, in 8min).

Done when: every existing formatRelativeTime consumer displays the compact form; the comment/reply timestamp appears beside the author name rather than below Like/Reply; existing absolute <time title> values remain unchanged; future output remains distinguishable; and no identity, count, API, or other timestamp helper changes are included.

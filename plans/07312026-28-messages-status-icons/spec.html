Why

Plan 17 shipped 1:1 messaging with conversation-level read watermarks for inbound unread badges, but senders never see whether a message left, arrived, or was read. That gap makes the thread feel one-sided — especially after Plan 22 added live delivery.

Status icons are the sender-facing mirror of read receipts: lightweight feedback on every outgoing bubble without changing how messages are composed or stored beyond a single delivery timestamp.

What

On outgoing message bubbles in the thread view, show a three-state status indicator beside the timestamp meta row:

✓
Sent Open blue circle + check
✓
Delivered Filled blue circle + check
Seen Peer profile photo (tiny circle)

Semantics (web app, not phone):

  • Sent — REST send succeeded; message is in thread state.
  • Delivered — peer’s client received the message (socket ack) or peer loaded the thread via REST while offline.
  • Seen — peer’s conversation read watermark is at or after this message’s created_at (they opened/read the chat).

Deliverables:

  • Migration — messages.delivered_at (nullable timestamptz).
  • Backend — mark delivered on client ack + on peer listMessages fetch; expose peerLastReadAt on thread load; emit sender-facing realtime events.
  • SPA — MessageStatusIcon component; integrate in MessageBubbleRow; thread state + socket handlers in MessagesPage.
  • ProfileAvatar — add xs size (~16px) for Seen state.

Done when:

  • Sender sees Sent immediately after send; Delivered when peer receives; Seen when peer reads — matching visuals above
  • Live updates via socket while connected; poll/reload still correct when disconnected
  • No icons on incoming bubbles or unsent tombstones
  • Migration applied; typecheck/build green; acceptance rollup Passed or waived in writing

Context

Baseline (origin/dev)

  • messages — no delivered_at; read state only at conversation level
  • MessageBubbleRow.tsx — outgoing bubbles show timestamp on showMeta only; no status UI
  • MessageRealtime.conversationRead — notifies reader only; sender never learns peer read
  • ProfileAvatar — sizes sm|md|lg|xl; smallest is 40px (too large for Seen)
  • Plan 27 typing indicator (in flight) — shares frontend/src/api/socket.ts and src/realtime/io.ts; merge order: land typing first or rebase status branch before -x

Closest analogs

  • Follow: Plan 22 event constants mirrored in socket.ts; REST write + WS push; MessageBubbleRow meta row styling (text-[11px] text-muted-foreground)
  • Follow: Plan 25 ProfileAvatar shared sizing pattern
  • New: MessageStatusIcon.tsx — presentational; status derivation in a small util or hook

Event contract (new)

EventDirectionWhenPayload
message:ack client → server Peer receives message:new (not own message) { messageId: string }
message:delivered server → sender After delivered_at set { messageId, deliveredAt }
conversation:peer-read server → other participant After markRead { conversationId, peerLastReadAt, readerId }

API shape changes

  • GET .../conversations/:id (list messages) — add top-level peerLastReadAt: string | null
  • MessageView — add deliveredAt: string | null (null for incoming or when not yet delivered)

Constraints

Must

  • Show three distinct visuals matching user spec
  • Outgoing bubbles only
  • Respect participant + friendship gates on ack handler
  • Sender-facing read notification (not just reader inbox bump)
  • Keep REST send/unsend/react paths unchanged

Must not

  • Store per-message read timestamps (watermarks suffice)
  • Show status on unsent tombstones
  • Block send on ack failure
  • Add npm dependencies for icons (SVG / lucide)

Out of scope

  • Inbox row status previews
  • Read-receipt privacy toggle / settings
  • Group chats
  • Push notifications

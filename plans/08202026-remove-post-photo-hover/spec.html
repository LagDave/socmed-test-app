Remove Post Photo Hover Effect

Why

Posted photos currently scale slightly when hovered in the feed. The requested interaction is a static photo presentation: hover should not zoom or otherwise transform a post’s image.

What / locked behavior

  • Remove the hover-driven transform from the single-photo feed image in PostCard.tsx.
  • Remove the group-hover-driven transform from every cell of the multi-photo feed grid in PostMediaGallery.tsx.
  • Keep the photo links, keyboard focus styling, image crop/size, border/radius, loading behavior, multi-photo count overlay, and post-detail photo presentation unchanged.
  • “Photos posted” is interpreted as normal feed post media in both one-photo and multi-photo layouts. Profile avatar/cover photo hover affordances, composer controls, reaction controls, and unrelated hover states are excluded.

Context and consumer inventory

SurfaceCurrent behaviorProtected consumers / behavior
Single-photo feed postPostStandardMedia renders the image within its existing post-detail link. The image has transition-transform duration-300 hover:scale-[1.01].Keep Link to={postPath}, its border/radius/container, image source/crop/alt behavior, and navigation to the post detail route.
Multi-photo feed postGridCell renders grid images inside a group link. Each image has transition-transform duration-300 group-hover:scale-[1.02].Keep the group link, grid layouts for 2/3/4+ photos, +N overlay, image source/crop/alt, and navigation to the post photos anchor.
Protected exclusionsDetail-gallery slides do not carry a hover scale.ProfilePage.tsx cover-photo effects, composer/photo controls, generic button/card hover styles, and all backend/API/data contracts remain untouched.

Closest analog: the detail-view image classes already render static post photos. Execution should remove only the transform-transition and hover-scale utilities from the two discovered feed renderers, without adding a CSS override or a new abstraction.

Constraints

Must

  • Read each target immediately before modifying it and reconfirm the image/link consumers.
  • Apply the same static behavior to both single- and multi-photo feed posts.
  • Keep keyboard and pointer navigation intact.
  • Run type-check, build, lint, and applicable convention checks; update the Revision Log if scope changes.

Must not

  • Do not change routes, media data, links, image dimensions/cropping, overlays, accessibility labels, or loading strategy.
  • Do not alter profile-photo effects or unrelated hover styles.
  • Do not add dependencies, create a global CSS override, or refactor media components.

Out of scope

  • Post-detail gallery styling and per-photo actions.
  • Profile/avatar/cover photo interactions.
  • Any feed layout redesign, animation-system change, or backend/API work.

Risk & mitigation

Level 1 — Suggestion. This is a narrow visual change, but both feed-media render paths must be handled; changing only the single-photo path would leave the hover zoom active for multi-photo posts. The mitigation is a direct two-file audit and behavioral checks at desktop and narrow widths.

Boundary: Remove only the image-transform classes. Link, focus-visible, and overlay classes remain because they are interaction and accessibility affordances, not the requested hover zoom.

Grill — decisions required before execution

QuestionRecommended answerWhy it matters
G1 — Which feed photos should center?
Only multi-photo grids shown in the screenshot, or both single- and multi-photo standard posts?		 Both standard single- and multi-photo posts. They use the same media-stage wrapper. Centering only grids would create an inconsistent feed and require a special-case selector.
G2 — What desktop width should the centered media use?
Restore the existing 36rem cap, or choose another maximum width?		 Restore 36rem. That exact responsive rule already exists in the stylesheet and was introduced for centered media; restoring it is the smallest, lowest-risk correction.
G3 — Should post detail follow the same correction?
The shared stage is rendered by both the feed and post-detail card.		 Yes, restore the shared centered stage on both. A CSS-only restoration returns the earlier intended behavior everywhere this wrapper is used. Choosing feed-only requires a component modifier and expands the change to PostCard.tsx.
G4 — How should it behave on mobile? Fluid at the available content width. The max-width should constrain only wider viewports; a fixed desktop width would cause narrow-screen overflow or wasted space.
G5 — Are profile-activity images, profile timeline posts, and compact shared embeds in scope? No; leave them unchanged. They use separate layout paths. Including them turns a targeted feed repair into a broader media redesign without evidence that they need it.
G6 — Is a CSS-only regression repair acceptable?
No grid redesign, new gallery controls, API work, or dependency.		 Yes. The fault is the CSS cascade. Keeping the repair to the conflicting declaration protects the media component and its interaction behavior.

Why

The feed's post-photo grid is laid out inside the text column that begins after the author avatar, so it appears shifted to the right of the post card's actual center. The screenshot confirms that a width-only CSS restoration cannot deliver the desired design.

What

Render standard post media as a card-level block, below the avatar/header row, so its 36rem responsive stage is centered against the whole post card. Render standalone shared-post embeds below the sharing post's header row, then center the original media within that full-width embed using the normal feed-gallery proportions. When a multi-photo preview is opened, land at the first photo in the detail album—not at comments. At smaller widths media remains fluid at 100% width.

Done when: the centerline of a single-photo post, a 2–10 photo preview, and the whole shared-post embed matches the centerline of its enclosing feed card on desktop; neither overflows or becomes unnecessarily narrow on mobile; clicking a multi-photo preview opens the detail page at its first photo without focusing or scrolling to comments; profile-activity media, profile timeline, and compact share-composer preview retain their respective layouts.

Context

  • frontend/src/components/PostCard.tsx currently renders PostStandardMedia inside the header's min-w-0 flex-1 text column. Its post-media-stage is therefore centered in the remaining width after the avatar, not in the card. Move only standard media to a card-level sibling below that header row.
  • frontend/src/components/SharedPostEmbed.tsx renders the original post media inside its own min-w-0 flex-1 column beside FriendPresenceAvatar. Move only the non-compact original media below that row; SharePostPreview stays compact.
  • A standalone share still renders SharedPostEmbed inside the sharing post's min-w-0 flex-1 column in PostCard. Move that whole embed below the outer header row; its internal centering then aligns with the full feed card.
  • SharedPostEmbed currently passes mode="compact" for a multi-photo original, applying the short compact-grid height. Use mode="feed" there only; SharePostPreview keeps mode="compact".
  • PostMediaGallery currently links multi-photo previews to /posts/:id. PostDetailPage contains the first-photo album at id="photos", but always passes composerAutoFocus to its comment section. Navigate previews to #photos, scroll there after data loads, and autofocus only on intentional #comments links.
  • frontend/src/components/PostMediaGallery.tsx owns the 2-, 3-, and 4+-photo preview grids. It should not change for this layout repair.
  • frontend/src/index.css defines the intended width: min(100%, 36rem) and centering at lines 1013–1018, but a later duplicate .post-media-stage { width: 100%; } at lines 1854–1856 wins in the cascade.
  • frontend/src/components/SharedPostEmbed.tsx uses compact media directly and does not use post-media-stage.
  • Closest analog: commit a602a92 introduced centered feed media galleries; no new component or design pattern is needed.

Out of scope: changing photo aspect ratios, creating a lightbox, redesigning the album preview, or centering unrelated feed content.

Do not add a second gallery abstraction or duplicate selector.

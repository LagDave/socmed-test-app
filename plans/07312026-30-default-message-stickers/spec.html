Why

Message threads already support four reaction “stickers” (👍❤️😂😮), but the UX is a hidden click-to-toggle strip — unlike the feed’s hover/hold ReactionBar. Facebook/Messenger ships six default reactions and makes emoji easy to send in the compose bar. Users want the same sticker set and the ability to pick multiple emoji when chatting — without waiting for full sticker packs or a proprietary art pipeline.

What

  • Expand reactions to the Facebook/Messenger default six: Like, Love, Haha, Wow, Sad, Angry — Unicode equivalents (👍 ❤️ 😂 😮 😢 😡).
  • Message thread reactions — replace the bespoke MessageReactionPicker floating strip with the shared ReactionBar interaction (hover or hold-to-expand, hover labels, pop animation, summary cluster). Surface: /messages/:conversationId only.
  • Composer emoji picker — emoji button in the thread compose bar opens a curated grid; tapping emoji inserts at the textarea cursor so users can send messages containing multiple emoji characters (plain text body — no new message type).
  • Backend — migration extends PG enum reaction_emoji; shared REACTION_EMOJIS constant and Zod schemas accept sad and angry on posts, comments, and messages.

Constraints

Must

  • Keep one reaction per user per message (unique message_id + user_id)
  • Extend shared allow-list in one constant (backend + frontend types stay in sync)
  • ReactionBar message mode uses existing PUT/DELETE reaction endpoints
  • Composer emoji inserts at cursor; does not auto-send
  • Hide reaction UI on unsent messages (unchanged)
  • B&W tokens; light + dark readable
  • Constitution layering — no reaction business rules in presentational components beyond API calls already in ReactionBar

Must Not

  • No new npm emoji-picker dependency without Revision Log justification
  • No sticker pack tables or sendable sticker message type
  • No arbitrary-string emoji reactions (stay on six-key allow-list)
  • No inbox last-message reaction preview
  • No multi-react rows per user per message

Out Of Scope

  • Image/GIF sticker packs, custom sticker uploads
  • Full Unicode emoji keyboard (1000+ glyphs) or category tabs
  • “Tap + for any emoji” custom reaction (Messenger long-tail)
  • Reaction animations beyond existing pop/wiggle CSS
  • Per-user default reaction preference

Risk

Level 2 — Concern. PG enum migration is irreversible in production without care; shared reaction type touches feed + messenger.
